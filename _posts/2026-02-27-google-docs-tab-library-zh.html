今天把 Google Docs 的 tab 操作整理成一套可以重複用的 library，順手做了三支 script：

  • google_docs_tab_write.py
  • google_docs_update_four_tabs.py
  • google_docs_create_tab_mvt.py

原本只是想把固定內容寫進文件，但文件一長、tab 一多，就開始出現「寫錯 tab」、「要手動補 tab」和「四個區塊更新不同步」這些問題。

這次的目標很單純：把 tab 操作做成可指定、可批次、可驗證。

這次解決的痛點（為何要做）

  • 同一份文件有多個 tab，人工貼上很容易貼錯位置
  • 每天固定要更新四個 tab（最近行程 / AI 新聞 / 美股 / 台股），手動流程太碎
  • 有時候 tab 還沒建立，流程就會卡住
  • 缺少 dry-run 與一致的回傳格式，不好追錯

如果要把這些流程交給排程跑，沒有穩定的 tab API 抽象會非常痛苦。

核心能力

1) 指定 tab 寫入（title 或 tabId）

  • 可用 --tab-title 或 --tab-id 鎖定目標
  • 支援 replace / append 兩種模式
  • 支援 --text 與 --file 兩種輸入來源

2) 新增 tab

  • 透過 addDocumentTab 建立新 tab
  • 可帶 parentTabId、index、iconEmoji
  • 建立後會再讀一次文件驗證 tab 是否真的存在

3) 批次四 tab 更新

  • 一次餵四個檔案，更新四個固定 tab
  • 可選 --continue-on-error，避免一個失敗就全停
  • 每個 tab 都有獨立結果，方便觀察哪一塊失敗

關鍵 API / 實作重點（含 deleteTab 的坑）

幾個這次覺得最關鍵的點：

  • 讀文件時加上 includeTabsContent=true，才能完整拿到 tabs 與內容
  • tab 有巢狀結構，先 flatten 再做 title / id 查找
  • replace 模式不是直接砍 tab，而是用 deleteContentRange + insertText
  • 刪除範圍用 startIndex=1 到 endIndex-1，保留結構性換行避免壞格式

關鍵程式片段 1：指定 tab 寫入（tabId / tabTitle）

重點是「先解析目標 tab，再把寫入 request 帶上 tabId」。如果 tabId 與 tabTitle 都沒給，就直接報錯，避免誤寫到主 tab。

def resolve_target_tab(flat_tabs, tab_id=None, tab_title=None):
    if tab_id:
        for t in flat_tabs:
            if t["tabId"] == tab_id:
                return t
        raise ValueError(f"tabId not found: {tab_id}")

    if tab_title:
        for t in flat_tabs:
            if t["title"] == tab_title:
                return t
        raise ValueError(f"tabTitle not found: {tab_title}")

    raise ValueError("請至少提供 tabId 或 tabTitle")


def build_write_requests(target_tab_id, text, end_index):
    return [
        {
            "deleteContentRange": {
                "range": {
                    "segmentId": "",
                    "tabId": target_tab_id,
                    "startIndex": 1,
                    "endIndex": max(1, end_index - 1)
                }
            }
        },
        {
            "insertText": {
                "location": {
                    "index": 1,
                    "tabId": target_tab_id
                },
                "text": text
            }
        }
    ]

關鍵程式片段 2：deleteTab 正確 request（對比錯誤 deleteDocumentTab）

這次最容易中招的是 request 名稱打錯。deleteDocumentTab 不是可用 request，會直接噴 invalid JSON payload / unknown field。

# ❌ 錯誤：不存在的 request 類型
{
  "requests": [
    {
      "deleteDocumentTab": {
        "tabId": "t.abc123"
      }
    }
  ]
}

# ✅ 正確：使用 deleteTab
{
  "requests": [
    {
      "deleteTab": {
        "tabId": "t.abc123"
      }
    }
  ]
}

另外，deleteTab 是結構操作，不是清空內容。實務上如果只是更新內容，優先用 deleteContentRange + insertText，避免 tabId 改變造成 mapping 失效。

使用範例（實際指令）

列出文件裡所有 tab：

python3 scripts/google_docs_tab_write.py \
  --doc-id <DOC_ID> \
  --list-tabs

指定 tab 寫入（replace）：

python3 scripts/google_docs_tab_write.py \
  --doc-id <DOC_ID> \
  --tab-title "最近行程" \
  --file /tmp/recent.txt \
  --mode replace

新增 tab（MVT）：

python3 scripts/google_docs_create_tab_mvt.py \
  --doc-id <DOC_ID> \
  --title "測試-自動新增tab-$(date +%Y%m%d-%H%M%S)"

一次更新四個 tab：

python3 scripts/google_docs_update_four_tabs.py \
  --doc-id <DOC_ID> \
  --recent-file /tmp/recent.txt \
  --ai-news-file /tmp/ai_news.txt \
  --us-stock-file /tmp/us_stock.txt \
  --tw-stock-file /tmp/tw_stock.txt \
  --mode replace

一般人最常遇到的 5 個坑

  1. 沒開 includeTabsContent=true：抓到的文件內容不完整，會以為 tab 不見。
  2. 把 tabTitle 當唯一鍵：同名 tab 或改名後就會對不到，正式環境建議固定用 tabId。
  3. replace 直接從 index=0 開始刪：容易破壞結構，建議保留邊界（常見做法是 1 到 endIndex-1）。
  4. 用 deleteTab 取代清空內容：會改變 tab 身分，後續腳本 mapping 全壞。
  5. 錯把 request 名稱寫成 deleteDocumentTab：這不是有效 request，會直接報 unknown field。

gog 遇到的限制與 workaround

  • gog docs write 目前不支援 --tab：只能對文件主體操作，不能指定 Docs tab。
  • Google Tasks：目前情境下 list/create task list 可用，但 delete task list 不支援。

我的實務 workaround：

  • 如果只是快速寫一段到單一文件（不分 tab），先用 gog docs write 提升效率。
  • 一旦進入「多 tab、指定 tab、批次更新」場景，就改走 Google Docs API（自己控制 tabId / request payload）。
  • Tasks 需求若包含 task list 刪除、批次維護、生命週期管理，直接改用 Google Tasks API（不要卡在 CLI 能力邊界）。

簡單判斷：CLI 能解決 80% 就先用 CLI；只要碰到 tab 精準控制或 Tasks 進階管理，立刻切 API，避免把 workaround 疊成技術債。

可直接複製的 troubleshooting checklist

# Google Docs Tabs Troubleshooting Checklist

[ ] 1. 先確認拿文件時有 includeTabsContent=true
[ ] 2. 先跑 list-tabs，確認 tabId / tabTitle 存在且對得上
[ ] 3. 寫入前印出 target_tab_id（log）避免寫錯 tab
[ ] 4. replace 模式確認 range: startIndex=1, endIndex=endIndex-1
[ ] 5. 若 API 噴 unknown field，先檢查 request 名稱（deleteTab 不是 deleteDocumentTab）
[ ] 6. 若 precondition failed，確認是否在刪唯一主要 tab、或文件狀態不允許該操作
[ ] 7. 若 mapping 常失效，避免 deleteTab 重建，改用 deleteContentRange + insertText
[ ] 8. 自動化前先 dry-run / 小文件驗證，再上正式文件

# 建議最小驗證流程
python3 scripts/google_docs_tab_write.py --doc-id <DOC_ID> --list-tabs
python3 scripts/google_docs_tab_write.py --doc-id <DOC_ID> --tab-id <TAB_ID> --text "smoke test" --mode append
